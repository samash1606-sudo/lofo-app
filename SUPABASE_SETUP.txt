LoFo Supabase Setup

LoFo uses Supabase Auth for accounts, Postgres for shared items, and Storage for
photos. The project URL and public anon/publishable key go in LoFo.html. Never
put a service-role or secret key in a browser page.

1. In Supabase SQL Editor, create the items table if it does not already exist:

create table if not exists public.items (
  id bigint primary key,
  name text not null,
  category text not null,
  status text not null check (status in ('lost', 'found')),
  location text not null,
  date date not null,
  image text not null
);

alter table public.items enable row level security;
2. In Storage, create a public bucket named `lofo-images` if it does not already
  exist. Public read access is needed to display item photos.
3. Open SQL Editor and run the complete migration in SUPABASE_ROLES_SETUP.sql.
  It removes the old anonymous write policies, makes all item changes require
  sign-in, and allows only Admin accounts to create items. Members can edit,
  mark found/lost, and delete existing items.
4. Create your first account from the LoFo sign-in screen. New sign-ups are
  Members by default. Confirm the email first if Supabase email confirmation
  is enabled, then sign in once so Supabase creates the member role row.
5. Promote your account to Admin. In Supabase SQL Editor, replace
  `ADMIN_EMAIL` with your account email in the commented SQL at the bottom of
  SUPABASE_ROLES_SETUP.sql, uncomment those lines, and run them. Sign out of
  LoFo and sign in again; the header should show Admin.
6. Other people can create their own accounts from the sign-in screen. They
  will automatically receive the Member role and cannot add new items.
7. In Supabase, open Database > Replication and enable Realtime for public.items.
8. Copy the Project URL and anon/publishable key from Project Settings > API.
  Keep only the publishable/anon key in LoFo.html; never expose a service-role
  key.

The migration configures upload, update, and delete policies for signed-in users
on the lofo-images bucket. The bucket itself remains public so photos can be
displayed by their public URLs.

9. Push this project to GitHub. GitHub Actions publishes LoFo.html and its assets
  to GitHub Pages. Set Settings > Pages > Build and deployment source to GitHub
  Actions if it is not already selected.

GitHub Pages serves only static files; it does not run server.js or server.py.
The website requires a working Supabase project and the role migration before
users can sign in and manage items.

Security note:
The role is checked by Supabase Row Level Security, not only by hiding buttons.
Do not recreate public INSERT, UPDATE, or DELETE policies for items or photos.
Anyone can view the public site and public item photos, but only signed-in users
can change data. Only accounts promoted to Admin can add new items.
